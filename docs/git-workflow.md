# Git 提交规则

1. 不要改完代码就自动提交，等用户明确说"没问题，提交吧"
   或类似的话，才执行 git add + commit + push。

2. commit message 用简洁的中文，说清楚这次改了什么、为什么改，
   不要用"update"、"fix bug"这种没有信息量的话。
   示例："fix: 图片节点提示词面板关闭时防抖数据丢失"

3. 如果一次改动涉及好几个不同的点（比如前后修了好几个
   独立的 bug、改了好几个不相关的文件），拆成多个 commit
   分别提交，不要全部塞进一个 commit。

4. 提交前如果发现有临时调试代码（比如调试用的 localStorage
   写入、console.log），提醒用户是否需要先清理再提交。

5. push 之前，如果这次改动涉及后端接口变更、数据库 schema
   变更这种有风险的改动，先跟用户确认一遍再 push。
