# Canvas Video Poster First

状态：已确认

决策记录：2026-10-11 用户确认四个关键点按推荐值执行——编辑面板复用会话元素一次到位；缩略图一档 480px WebP；上传/生成完成时预热海报。同日用户确认 Spec 整体，开始实施。实施中用户调整 hover 交互：节点不放播放按钮，沿用原 hover 播放逻辑（带声尝试、被策略拦截才静音降级，无时长上限），离开节点即卸载会话（下次悬停从 0 秒开始）；页面隐藏/窗口失焦/画布交互同样卸载，保持"隐藏期间无常驻缓冲"的根因修复。

## 目标

视频节点静止态不再持有带 `src` 的常驻 `<video>` 元素：静止显示首帧海报图，hover 按原交互挂载会话元素播放，播放/编辑才持有会话元素。根治"浏览器逐出常驻视频缓冲后调度器 60 秒超时、且失败态永久粘滞"的问题（现象：刷新正常，切走应用再切回出现"视频加载超时"遮罩，只能手动重试）。

## 背景（调查结论）

- 病根在 `web/src/features/canvas/services/video-load-scheduler.ts`：每个节点常驻一个挂真实 `src` 的 `<video>`；`loadedmetadata`/`loadeddata` 是一次性事件，`stalled` 置位后无自动恢复路径。
- 服务端海报能力已存在：`GET /api/files/<视频路径>?w=<宽度>` 对视频走 `getVideoPosterWebP`（ffmpeg 抽首帧 + 缩放 WebP，缓存于 `_cache/<w>/`，缓存键由存储键与宽度派生）；生成失败返回 404（约定：不回退原视频，由前端兜底）。**无需任何数据库变更**——海报是内容寻址的确定性派生品。
- 参考实现：open-ai-canvas-main 的 `canvas-video-hover-preview.ts`（临时元素 hover 预览）与 `canvas-node-media-content.tsx`（海报 + 激活挂载播放器）。

## 范围

- `web/src/features/canvas/` 内：`VideoNode`、`use-canvas-video`、`video-load-scheduler`（删除）、`CanvasMediaLoadingProvider`（移除视频调度器）、相关测试。
- 服务端仅一处可选增强：上传/生成完成时预热 480px 海报（fire-and-forget，失败不影响主流程）。
- 不改动：图片节点与图片加载调度器、资产库卡片、`/api/files` 路由、画布连线与交互、主题/音量等播放器 UI 逻辑。
- 历史视频不需要迁移：海报按需惰性生成，首次请求时由现有 ffmpeg 链路补齐。

## 业务规则

1. **静止态**：视频节点渲染海报 `<img src="<视频src>?w=480">`，经现有图片加载调度器做视口门控。不渲染 `<video>` 元素，不挂任何媒体 `src`。海报未就绪时显示视频图标占位；404 失败走 CanvasImage 既有失败态契约（图标 + 重试）。
2. **hover 播放会话**：鼠标悬停 300ms 后挂载会话 `<video>` 并播放（与播放/编辑共用会话元素），先尝试带声播放，被自动播放策略拦截才降级为静音；无时长上限，控件条在播放期间可用（暂停/进度/音量，与原逻辑一致）。以下任一条件立即卸载会话回到海报：鼠标离开节点（用户经控件条接管播放后除外，与原逻辑一致）、error、页面隐藏、窗口失焦、画布进入拖拽/连线等交互、hover 前置条件失效。会话卸载即释放解码器，下次悬停从 0 秒开始——隐藏期间不存在挂 `src` 的常驻缓冲，根因修复保持。
3. **播放会话**：没有独立播放入口（无播放按钮）——会话由 hover 意图驱动，控件条可暂停/续播（接管后离开节点不打断，与原逻辑一致）。**会话元素挂载条件只看显式需求**：hover 意图 || `panelOpen` || `cropOpen` || `busy !== null`；`playing`（元素播放事件的 UI 镜像）不得参与挂载判定——面板经注册表播放/恢复源时 `load()` 不触发 pause 事件，镜像会卡在 true，元素将赖着不卸载（图标停在暂停、hover 失效）。镜像由渲染期派生重置作废（元素不在会话中即作废）。**面板/裁剪打开即收编元素所有权**：hover 会话立即结束，此后面板驱动的播放（循环预览、scrub）不受 mouseleave/隐藏的 hover 结束逻辑影响；**面板/裁剪退出即整体卸载回封面**，播放状态随实例拆除作废。会话不跨实例恢复 `currentTime`，每次挂载从 0 秒开始（面板内的位置保持由注册表负责）。
4. **会话期间海报垫底**：`<video>` 从挂载到解出首帧之间是透明的，若卸掉海报会闪黑场。会话渲染时海报垫在视频下层不解除，视频出帧后自然盖住（同比例 `object-contain`，边缘对齐），挂载→播放→卸载全程无闪烁。
5. **上传/生成中**：沿用现有上传进度与生成遮罩，其下显示海报占位（此时海报尚不存在，显示图标），不挂视频 `src`（本地 `previewUrl` 预览仅在现有上传遮罩内使用，行为不变）。
6. **视频加载调度器退役**：`VideoLoadScheduler`、`useCanvasVideo` 的租约/优先级/60 秒超时/粘滞 `stalled` 机制整体删除；视频不再做视口外元数据预取（海报承担可视性）。`media-visibility` 与图片调度器保持不变。
7. 失败不粘滞：会话加载失败显示"视频加载失败"遮罩并提供重试（重试 = 重挂会话元素，hover 会话的重试同时重新武装自动播放）；hover 起播失败（play 被拒且非策略拦截）静默回到海报。

## 技术影响

- 纯前端为主：`VideoNode.tsx` 重构媒体渲染分支；hover 播放复用会话元素（原交互逻辑平移，不再有独立临时预览模块）；`use-canvas-video` 简化为会话挂载 hook；删除 `video-load-scheduler.ts` 及其测试；`CanvasMediaLoadingProvider` 只保留图片调度器。
- 服务端：视频文件落库（persistFileObject，含上传/生成/下载导入来源）完成后对 file object 发起一次 `getVideoPosterWebP(storageKey, 480)` 预热（异步，不阻塞响应，失败仅记日志）。
- 视频尺寸来源不变（节点已存 width/height），海报 `<img>` 按节点尺寸 `object-contain`。
- **节点 `data` 形状零变更**：海报 URL 由 `src` 加 `?w=480` 推导，不在 `VideoNodeData` 新增字段；`upload`/`taskBinding`/`hasAudio`/`duration` 的语义与回填时机不变（`duration`/`hasAudio` 的回填载体从常驻元素改为会话元素）。保存/恢复、撤销、SSE 同步均不受影响。
- 会话元素按需挂载、随缘卸载，不参与任何加载调度；无并发排队机制（与原交互一致，多节点同时悬停各自成会话）。

## 异常与边界

- 海报首次请求触发 ffmpeg（超时 30s 兜底）：预热使常规路径命中缓存；未命中时 hover/播放不受影响（海报迟到最后才显示，占位图标先出）。
- 损坏/无法抽帧的视频：海报永久 404 → 图标占位；hover/播放仍可尝试（由浏览器报错走播放失败遮罩）。
- 大量视频同时进入视口：海报走图片调度器既有并发与优先级；播放会话用户驱动，天然串行。
- 移动端/触屏：hover 由 mouseenter/leave 驱动，触屏无 hover，直接点按节点选中（与原行为一致）。
- 会话元素销毁时机与编辑互斥状态机（`busy` 四类互斥）不变，只随挂载条件联动。

## 验收标准

- 静止的视频节点 DOM 中不存在带 `src` 的 `<video>`；切走应用再切回不出现"视频加载超时"遮罩（原复现路径）。
- hover 播放沿用原交互：悬停 300ms 起播（带声尝试）、离开即停并卸载；控件条暂停/拖动进度/音量可用；拖拽画布、切走应用立即停止。
- 控件条在会话期间可完整使用暂停/进度/音量（循环随片段面板语义开关，非控件条按钮）；面板打开期间播放位置经注册表保持；会话关闭后解码器释放（元素移除、`src` 清除）。
- 抽帧、片段截取、画面裁剪、分离音频面板行为与现状一致（回归测试通过）。
- 上传中/生成中/海报 404 三种状态显示占位，无报错噪音。
- 删除 `video-load-scheduler` 后全量 server/web 测试、typecheck、lint 通过；新增 hover 会话与海报渲染的单测。
